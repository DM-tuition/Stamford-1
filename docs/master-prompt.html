Stamford House Website

Master Context Document & Build Brief — everything an unfamiliar assistant needs to continue this project. Generated June 2026.

One-line summary: A static, dark-first, animation-rich marketing/community website for Stamford House at Altrincham Grammar School for Boys (AGSB), featuring a live, filterable house-events calendar. Plain HTML/CSS/JS — no build step. Lives on the main branch of GitHub repo dm-tuition/stamford-1.

1. What this project is

  • Purpose: Public/internal site for Stamford House — promote the house, show its identity & legacy, list the year's competitions, and let students get involved.
  • Audience: Stamford students (all year groups), prospective members, the wider AGSB community.
  • Owner/contact: dmtuition2026@gmail.com. Built for the 2026/27 Stamford leadership (Captain Daniel Stevenson, Vice Captain Ayaan Siddiqui).
  • Repo: dm-tuition/stamford-1  |  Branch: main (everything is committed and pushed here).

2. Tech stack & architecture

  • Pure static site — no framework, no build, no package manager. Just HTML + CSS + vanilla JS.
  • Fonts: Google Fonts — Space Grotesk (display/headings) + Inter (body).
  • No external JS libraries — all animation/interactivity is hand-written vanilla JS (deliberately, so it works offline and has zero dependencies).
  • Data-driven calendar: the Events page fetches data/events.json at runtime and renders it.
Important gotcha: because the calendar uses fetch(), the site must be served over HTTP, not opened via file://. Locally: python3 -m http.server 8000 then visit http://localhost:8000. (All other pages work fine from file://; only the calendar needs a server.)

4. Design system

Palette (CSS variables in :root)

  • Royal #2a4bff · Royal-bright #4d6bff · Steel #2f8fd0 · Cyan #6fd6ff · Light #d8e9f5
  • Dark surfaces: bg #04081e, bg-2 #070d2a; text #eaf0ff, muted #93a4cf.
  • Dark-first with a light theme via html[data-theme="light"], toggled by the ☀/☾ button (persisted in localStorage key stamford-theme).
  • No rival-house colours in the brand (red=Bradbury, green=Massey, yellow=Tatton). They appear only in the flag strip and the Senior Prefect Team cards.

Key reusable classes

.glass (frosted card), .card, .btn .btn--primary/.btn--ghost, .section, .eyebrow, .section-title, .gradient-text, .reveal (+ .d1/.d2/.d3 stagger), .split, .grid .grid-2/3/4, .spotlight, .person, .scoreboard, .timeline, .cta-band, [data-tilt], [data-spy].

5. The crest / logo system

  • Every crest <img> uses src="assets/crest.png" with onerror fallback to assets/crest-photo.jpeg. The favicon points to assets/crest.png.
  • To change the crest: replace assets/crest.png (transparent PNG recommended). It updates nav, hero, footers, captain badges, preloader and favicon at once.
  • Hero crest size is set in CSS: .hero-crest img { width: min(480px, 86vw) }.
History note: the crest went through several iterations (flat SVG → textured photo → background-removed cutout → refined gold-framed enamel PNG). The current/approved one is the refined gold-framed transparent PNG at assets/crest.png.

6. JavaScript features

js/main.js (every page)

  • Preloader (crest + load bar, centered), film-grain overlay, skip-to-content link, focus-visible.
  • Light/dark theme toggle (persisted); mobile nav; footer year auto-fill.
  • Scroll-progress bar; header hides on scroll-down / shows on scroll-up.
  • Custom glowing cursor; magnetic buttons; 3D crest tilt; card tilt ([data-tilt]).
  • Scroll-reveal (IntersectionObserver); count-up numbers; animated scoreboard bars.
  • Particle "starfield" canvas; drifting background orbs in heroes.
  • Flair: floating per-letter hero wordmark; letter-by-letter heading reveals; flowing gradient text; glare sweep on cards/buttons; blue sparkle burst on primary buttons / theme toggle / flagship cards.
  • Quote carousel; scroll-spy dots (built from [data-spy] sections on the home page); page-transition curtain.
  • Global helpers: window.stamfordToast(msg, icon), window.stamfordSparkle(x,y,count), window.stamfordCountUp(el).
  • Everything respects prefers-reduced-motion (animations disabled / instant).

js/events.js (events.html)

  • Fetches data/events.json; renders cards grouped by month.
  • Filters: type (Sport / Academic / Arts / Performance / Social) with live counts, and year group.
  • Live text search; grid/list view toggle; jump-to-month nav.
  • Countdown to the next dated event (relative to today).
  • "Add to calendar" generates a downloadable .ics per dated event.
  • Season stats computed live (totals by category, months).

7. Events data model (data/events.json)

Top-level: meta, categories (array), events (array). Each event:

FieldMeaning
titleEvent name (flagship House Shout marked with flagship: true).
staffStaff lead / organiser.
dateISO date (YYYY-MM-DD) or null if TBC. Drives countdown + .ics.
dateLabelHuman label shown on the card (e.g. "Thu 16 Oct", "Feb – May", "TBC").
monthGroup header (e.g. "October 2025"). Sept–Dec = 2025, Jan–Jul = 2026.
yearGroup, numberWho it's for, and participant count/notes.
ethosArray of tag words.
notesFree-text details.
categoryOne of the 5 categories (drives filtering + colour).

Transcribed from the school's "25-26 Events" PDF (the Annual House Events Calendar 2025/26): ~88 rows across Sept 2025 → Jul 2026. Flagship events include House Shout (Oct), and the season ends with Sports Days (30 Jun / 1 Jul).

Data caveat: a few cells in the source PDF looked column-shifted (some cricket "Year group/Number" values). They were transcribed as-shown rather than guessed — worth a human check before treating as authoritative. Also the source's "December 2024" header is treated as Dec 2025.

9. How to run & deploy

  • Local: python3 -m http.server 8000 in the repo root → http://localhost:8000.
  • Deploy: any static host. Recommended: GitHub Pages (serve main at root) — not yet set up. Netlify/Vercel also work with zero config.
  • Git workflow: commit + push to main. (Earlier work used branch claude/website-first-draft-87H4Y, since merged.)
